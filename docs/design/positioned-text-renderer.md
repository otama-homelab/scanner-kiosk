# Positioned OCR text renderer

`pdftextlayer.RenderPositioned` creates one invisible text-only PDF from a validated positioned page and a caller-approved TrueType font. It embeds the complete font, assigns explicit CID-to-glyph mappings and Unicode mappings, and scales each horizontal span to its supplied line box. Input pixels become page coordinates with the top-left origin converted to PDF coordinates. Provider span order is preserved. Page rotation remains a later composition step.

It rejects unsupported font formats, missing glyphs, invalid geometry, more than 10,000 spans, more than 8 MiB of text, more than 65,534 distinct characters and fonts over 32 MiB. Output writes obey the caller's byte limit and cancellation returns no partial PDF. The JSON reader must separately enforce byte limits before decoding. A trusted renderer output can enter the existing Overlay path; arbitrary remote PDF output remains untrusted.

The LLM adapter accepts optional `TextLayerFont` bytes and `MaxTextLayerBytes`. With a validated font, positioned models additionally expose `pdf_text_layer`; the profile, renderer version and font digest determine the pinned model version. It requests positioned JSON from the endpoint, validates it, renders locally and allocates only the resulting PDF artifact. Text-only profiles do not acquire this capability. `SCANNER_OCR_LLM_TEXT_LAYER_FONT` optionally supplies an absolute clean path. The config loader validates metadata without file I/O; worker composition reads a regular file with a 32 MiB bound and constructs the renderer with the OCR result byte limit. A missing/invalid configured font fails optional OCR initialization rather than substituting a font. An empty path preserves the original capabilities. No font is installed or mounted by default. The caller must load a license-approved font, account for font/input/output memory and disk budgets, and bind the positioned artifact to immutable page identity before rendering. Full font embedding increases output size. Current rendering follows horizontal advances without shaping, bidi reordering or vertical writing; it does not establish recognition accuracy, word selection alignment or accessibility reading order. Those require real-document acceptance before advertising LLM searchable-PDF support.

Local tests validate the PDF, overlay composition, independent Poppler extraction of escaped Latin text and Japanese/English, all-white rendered layer pixels, invalid input, missing glyphs, cancellation and byte limits. Go's existing font fixture covers default tests; a Japanese fixture is enabled by SCANNER_TEST_POSITIONED_FONT. Fonts used in tests are not copied into the repository or runtime image. The current evidence receipt identifies the exact fixture and code hashes.

The coordinate regression independently parses Poppler bbox XML for a single word in two differently sized boxes near the top and bottom of a page. All four rectangle edges must match the requested box within 0.1 page units. Blank pages validate and compose, and a byte limit exactly equal to the generated output succeeds while one byte less fails. These synthetic horizontal cases do not establish vertical writing, multi-column reading order, rotated final-page selection geometry or real OCR box accuracy.
