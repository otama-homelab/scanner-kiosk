# OCR catalog resolution

`renderadmission.CatalogResolver` validates a worker-authored metadata snapshot and pins an exact model version and quality preset for new OCR admission. It consumes the OCR plugin contract without constructing a provider, reading its endpoint or credentials, probing it, or sending document data. `ocrplugin.CopyCapabilities` shares validation and returns detached model/language/preset/output slices. Invalid UTF-8 metadata is rejected.

Snapshots have publication and expiry timestamps, bounded provider/model/preset counts and a maximum five-minute lifetime. Future/expired/invalid snapshots and malformed provider/default metadata are unavailable. Duplicate provider/model/language/preset/output entries are rejected through shared contract validation. Missing required default quality is unavailable rather than selecting the first advertised preset. Models without presets can use an explicit empty default.

Selection matches exact provider/model IDs and advertised languages, with no duplicates. It honors an explicit supported preset, or the snapshot's explicit model default. It pins the advertised model version. Browser-supplied versions and unsupported selections are rejected. The current installed pipeline accepts native searchable PDF or invisible PDF text layers; text/positioned-text-only output still needs a renderer and is not silently treated as searchable PDF. The resolver returns model page/pixel bounds with version and preset. The service intersects pixel bounds with deployment policy; the document store checks page count and immutable validated source dimensions in the admission transaction before any revision/output/reservation change. Unknown dimensions or incompatible pages return HTTP 422. Receipt replay occurs before current model limits are checked.

The service preserves `ErrUnsupported`, mapped to HTTP 422. Missing, stale or failed capability access remains a generic 503 without private source/provider detail. Existing receipt lookup precedes resolution, so provider changes do not re-execute an already accepted command. There is no implicit model change or OCR-to-plain fallback.

The [SQLite publication/source](worker-catalog-storage.md) fences worker boot/generation and expiry. The worker lifecycle now registers after its recovery gate, refreshes metadata and withdraws it on graceful shutdown. API composition installs the read-only reader and resolver. Current publications allow OCR selection at the HTTP boundary; missing/stale publications return 503. Wall-clock freshness is leased metadata, not instantaneous liveness or provider-health proof. The authenticated [public capability projection](capability-http.md) is connected. The worker also publishes its configured preferred selection, validated against model languages/presets and copied independently. The output dialog consumes the public projection. Scanner capability publication and restart recovery remain pending. Plain PDF/image processing remains available.

Tests cover version/default pinning, explicit quality, preset-free models, expired/future/overlong snapshots, malformed/duplicate metadata, unavailable defaults, unknown models, unsupported/duplicate languages, unsupported presets/renderers, client versions, expiry during resolution, safe source errors, detached metadata and service rejection without admission. These are metadata tests; they do not establish OCR accuracy, provider health or live API selection.
