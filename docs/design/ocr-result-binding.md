# OCR result-to-artifact binding

`ocrplugin.BindResult` verifies one provider result against the validated immutable request and coordinator-supplied sealed artifact summaries. The provider cannot supply authoritative file metadata. The model version must match the pinned request, and each requested page must reference exactly one distinct produced artifact of the requested native output kind. Missing/duplicate/foreign pages, duplicated or unscoped outputs, original-input aliases, wrong kinds and unreferenced artifacts are rejected. Result ordering is normalized to request order without aliasing the provider array.

The complete sealed output list must fit the supplied byte budget using overflow-safe accounting. Empty plain-text output is valid for a blank recognized page; zero-byte JSON/PDF outputs are invalid. This checks metadata and total sealed output size, not OCR accuracy, PDF/JSON content, native scratch growth or total pipeline disk reservations. Registry model/capability validation must precede binding; format/geometry validators still follow it.

`ocrresult.BindSealed` adapts actual `artifactscope.Seal` records into this engine-independent contract and returns copied page/input and artifact records. Paths, size and SHA come from the coordinator's sealed scope, never the provider response. It does not publish, release or delete files and grants no user authorization. The caller remains responsible for scope lifetime and version/ownership/expiry checks at publication.

Unit tests cover ordering/copying, wrong version, missing/foreign/duplicate pages and artifacts, original aliases, wrong kinds, extra output, invalid size, exact/over-budget limits and blank text. The local LLM mock now binds its actual scoped text output through this contract. The real two-page Tesseract integration intentionally reverses provider results, binds sealed outputs through the product adapter and then runs the independently inspected image/PDF composition path.

Executable-worker OCR dispatch and the shared admitted-byte budget for OCR intermediates and final output are implemented in `renderjob.prepareOCR`; see [the worker pipeline](ocr-worker-pipeline.md). The result binder itself only checks sealed outputs against its supplied bound. Native scratch/watchdog acceptance, the LLM positioned renderer and native recovery acceptance remain separate requirements. This component does not claim that a provider recognized the right words; it proves identity/coverage/accounting consistency at the boundary.

`ocrresult.TestBindingUsesSealedScopeAndRejectsForeignOutput` exercises actual output writers and sealing without a native provider. It checks request order, coordinator-owned hash/path preservation, foreign-scope references, exact/over-budget behavior and detached returned metadata. This is boundary evidence, not renderer or OCR-quality acceptance.
